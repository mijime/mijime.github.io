# Flowdeck — 1人＋チームメイト3〜5人の協力型デッキ構築カンバン

## Purpose

カンバンの流れを、デッキ構築とリスクカードで体験する協力ゲーム。
プレイヤーは1人。選んだチームメイトと共有のタスク・納期に立ち向かう。
舞台は、コーディングエージェントと軽量LLMを開発・販売するSaaS企業。チームでエージェントとLLMを使い、事業で企業価値を伸ばす。

## コアループ

```
1ラウンド = 1日
各プレイヤー: 手札5枚 → 3アクションを1手ずつ → 手札を捨てる
全員終了 → 納期トークン +1 / 期限切れ処理 / Backlog補充 / 日付+1
```

- 人間が先手。編成したメンバー3〜5人が続く。UIのメンバーは3軸の重みを持つ
- ブラウザUIは `/apps/flowdeck/` で提供
- **個別デッキ**（各12枚）。手札5枚、1日3アクション
- 手番は1アクションずつ順番に回る（あなた → メンバー → あなた …）
- 手札は日開始時に5枚まで引き直し、手番終了時に捨てる
- アクションを使い切るとその日の手番終了。パスすると残りアクションを放棄し、その日はもう動けない
- 共有：タスク山札、Backlog 4枚、リスクデッキ、**Ready/In Progress/Review のチームボード**、企業価値、技術的負債
- 個人：デッキ・手札・捨て札
- WIP上限なし。Ready/In Progress/Review の合計を「見える化」指標として表示
- ゲーム長：**10 / 20 / 30日**（新しいゲームで選択）。レトロの自動除去はなし
- 全員のアクションが終わったら日末処理

## オンボーディング

初回起動時（セーブなし）は、1画面の導入を表示する。文章ではなく配置で説明する。

- レーンの流れ（Backlog → Ready → In Progress → Review → Done）を図で示す
- 企業価値・技術的負債・星評価の関係を数値と星で示す
- チームの性格軸（focus / greed / urgency）をアイコンで示す
- 日数とメンバー人数を選んで開始

- 一度見たら localStorage (`flowdeck:intro:v1`) に記録し、次回以降は表示しない
- セーブがある場合は復習用の閉じるボタン付きで表示する

## タスクとレーン

```
Backlog → Ready（設計） → In Progress（開発） → Review（テスト） → Done
```

- タスクには **設計 / 開発 / テスト要件**、**スコア**、**納期**、**報酬カード** が印刷されている
- タスクを引いた人が**担当者**。獲得者は貢献ポイント最多（同点は枚数→最後のカード）で決まり、報酬カードは獲得者の捨て札に入る
- 貢献ポイントは実際に置いた有効レベル（代用ありルールでは代用はlv1）の合計
- 共有ボードなので、誰のタスクにも設計/開発/テストカードを置ける（テスト支援の一般化）
- 報酬カードはタスクごとに印刷。スコアと報酬は独立
  - 高スコアタスクは弱いカード（設計lv2など）
  - CI/CD・リファクタ・ドキュメントなどスコア1の改善タスクは強いカード（lv3〜5）
- タスクに載せたカードは獲得まで固定。獲得時に各カードの持ち主の捨て札へ
- タスクはテーマと比率からゲーム開始時に完全自動生成する。通常42＋効果24＋インシデント6の構成。名前・スコア・報酬・納期・効果・罰則を毎回生成する
- 高スコアタスクはスコア6〜7
- 要求合計は `価値（スコア + 報酬lv×0.5 + 効果価値 + 罰則価値）/ 目標効率` で逆算する。通常0.30、高スコア0.31、効果0.29、インシデント0.34
- 効果タスクには効果の強さに応じてスコア1または2を付与する（コンテキスト/並列実行/LLMトークン/技術的負債-2は1、エラーバジェット/技術的負債-1/納期+1は2）
- スコア3タスクの報酬はlv3に統一する
- 効果カード6枚にLLMトークンを付与する（5枚+1、1枚+2）
- 全員が開始時にLLMトークン1個を持つ
- LLMトークンは個人トークン。手番中にアクションを消費せず、任意レーンのlv1作業として置ける
- リスクカードのドロー数は「作業ピース数（カード枚数 + LLMトークン数）÷ 要求合計」の比率で0〜3枚
- 生成結果は `taskDefs` としてstateに保存する（seed再生成だけに依存しない）
- 山札が尽きたら、完了・期限切れのタスク捨て札をシャッフルして山札に戻す
- インシデントは `kind: "incident"`。期限切れ時に `TaskPenalty` を解決する
- 罰則: 負債（全員/担当者） / 企業価値減 / 手札破棄 / 翌日アクション減
- リスクカードは16枚を使い回す
- リスクカードの内訳: 追加要件+1×6 / 追加要件+2×3 / 仕様変更×3 / 想定外の好機×2 / 問題なし×2
- 直接負債を増やすカードは廃止。負債はリスクを吸収できなかった結果としてのみ発生する
- ログは最新500件まで保持する
- セーブは localStorage と IndexedDB の両方に保存し、localStorage がない場合は IndexedDB から復元する
- タスク報酬カードはスコアを持ち、デッキに残っている間だけ企業価値に数える
- タスク報酬カードを廃棄するとスコアが消え、負債カードを廃棄すると負債が減る

## チームメイト

- 新しいゲームでメンバーを **3〜5人** 選ぶ。名前・アイコン・性格は開始時にランダム
- 性格は **focus / greed / urgency** の3つの符号付きの重み（`-1..+1`）
- アンカーや固定パターンはなし。各メンバーが独立に連続値を持つ
- `focus`: +で仕上げ（プレイ）、-で着手（Pull）
- `greed`: +で得点・報酬、-で整理・品質（テスト、負債や低レベルカードの廃棄）
- `urgency`: +で納期優先、-で長期・余裕優先
- 納期が近いタスクには性格に関係なく最低限の優先度（`URGENCY_BASE`）を足す。`urgency` がマイナスでも期限切れを放置しすぎない
- Pullは自分のWIPが多いほど強く抑制する。`focus` がマイナスでも引きすぎて詰まらない
- メンバーはタスク報酬カードを自分からは捨てない
- プレイ・Pull・廃棄を同じ重み付きスコアで比較する
- 代用ありルールでは、そのフェーズを完了できる場合だけ代用する
- メンバーは「このカードで要件を満たせるか」「効果を使えるか」を評価してカードを選ぶ
- タスク選択は「スコア＋報酬」を要求量で割った効率も見る
- リザルトには各員の設計/開発/テストのプレイ枚数・ポイントと、デッキ構成を表示する
- リザルト上部に「あなたの貢献」（作業pt、チーム内シェア、AI平均比、順位、獲得・報酬）を表示する。作業ptにはLLMトークン分も含む

## ルールセット

ルールは `packages/flowdeck/src/engine/rules/` に集約し、`RuleSet` としてゲーム生成に注入する。

- `effects/`: カード効果。1効果 = 1プラグイン（`apply` / `aiValue` / `label` / `describe`）
- `penalties/`: 期限切れ罰則
- `risks/`: リスクカードの解決
- `generation.ts`: タスク生成ポリシーの型。実装は `data/generateTasks.ts` の budget / value と `data/autoGenerate.ts` の auto
- `tips.ts`: ボードミーティングの指摘
- `balance.ts`: アクション数・手札・星閾値・リスクドロー比率

`createGame` / `reduce` / `playBotRound` は `RuleSet` を受け取れる。現在のルールセットは `base` のみ。

- `base`: 完全自動生成・価値-first・代用なし・開始トークン1個

追加手順は `src/engine/rules/README.md`。

## テスト

1. **品質ゲート**: テスト要件を満たさないと獲得できない
2. **リスク軽減**: テスト要件を超えた分だけ、リスクカードの要求を軽減
3. **チーム支援**: テストカードは誰のReviewタスクにも置ける
4. **リスクドロー数**: 作業ピース数が多いタスクほど、獲得時にリスクカードを多く引く

## リスクカード

獲得時に、作業ピース数（カード枚数 + LLMトークン数）÷ 要求合計 の比率で0〜3枚引く。

- 比率 `>= 1/2` → 3枚
- 比率 `>= 3/8` → 2枚
- 比率 `>= 1/3` → 1枚
- それ未満 → 0枚

例: 要求合計18なら 5枚→0 / 6枚→1 / 7〜8枚→2 / 9枚以上→3。

カード:

- 追加要件 +1 / +2（設計・開発・テスト）
- 仕様変更（任意フェーズの余剰で吸収）
- 想定外の好機（LLMトークン+1）
- 問題なし

解決:

- 追加要件は**合算せず、リスクカード1枚ごと**に判定する
- ベース要件を超えた余剰作業（フェーズごと）で各カードの要求を順に吸収する
- 仕様変更は任意フェーズの余剰で吸収する。大きい余剰から使う
- 追加要件を吸収できなかった場合は負債1。仕様変更は未吸収1単位につき負債1
- 直接負債を増やすカードは置かない。負債は「余剰で吸収できなかった結果」としてのみ発生する
- タスク自体は獲得できる（リスクを負って出す）

## レーンとカード種別

- 基本ルールでは、設計/開発/テストとも**同種カードのみ**置ける
- **テストはテストカード専用**。他種類では置けない
- テストカードはReview専用。印刷されたlvのまま使う（レーン依存の+1はしない）
- LLMトークンはどのレーンにもlv1作業として置ける（アクション消費なし）
- 初期デッキは各lv2以上

## デッキ構築

- 初期デッキ12枚: 設計/開発/テスト 各 lv2×2, lv3, lv4
- タスク報酬（タスクカード自身）、リスク未吸収の負債、1アクション廃棄でデッキが変化
- 手札1枚を1アクションで廃棄できる
  - 低レベルカードや負債カードの整理に使う
- カード強化はMVPでは入れない

## カード効果

一部の投資タスク報酬（lv3〜5）に効果を付ける。効果タスクのスコアは効果の強さで1または2。効果名はゲーム内の用語に合わせる（コンテキスト=ドロー、並列実行=追加アクション、技術的負債=負債除去、エラーバジェット=負債防止）。

- `自動テスト整備` / `CI 整備` / `ログ基盤` / `可観測性` / `テスト自動化`: コンテキスト+1（ドロー）
- `リファクタリング` / `リリース自動化`: 並列実行+1（追加アクション）
- `ドキュメント整備`: 技術的負債-1
- `期限交渉` / `日程バッファ`: 納期+1トークン
- `自動化` / `ペアプロ` / `ペアテスト`: LLMトークン+1
- `負債返済` / `負債圧縮`: 技術的負債-2
- `リリース凍結` / `仕様凍結`: 納期+1
- `エラーバジェット` / `ロールバック訓練`: エラーバジェット+1（次の負債を1枚防ぐ）
- `フルスタック化`: コンテキスト+1（ドロー）
- `クロスファンクショナル`: 並列実行+1（追加アクション）

LLMトークン付与も効果カードの一区分として扱い、専用テンプレート3枚から生成する。「LLMトークン付与」と「その他の効果」は分けて枚数を指定できる。

効果はカードをプレイした時に自動解決する。メンバーは効果込みでカードを選ぶ。

## 納期

- ラウンド終了時に、盤面の全タスクへ納期トークンを1個置く
- トークンが納期に達したらタスクはトラッシュ
- タスクに載っていたカードは持ち主の捨て札へ
- 通常タスクの納期切れによる追加負債はなし（機会損失とカードの足止めがペナルティ）
- インシデントの納期切れは `TaskPenalty` に従って罰則を適用する

## スコア

```
最終スコア = 企業価値 - 技術的負債 × 2 - 期限切れ罰則
```

- 5人・日数別の目標:

| 日数 | 負債上限 | 星 |
|---:|---:|---|
| 10 | 6 | 26 / 36 / 40 |
| 20 | 7 | 64 / 78 / 85 |
| 30 | 8 | 104 / 124 / 131 |

目標はランダム編成の分布基準。1星は下位25%、2星は上位25%、3星は上位10%。

- 企業価値はデッキに残っているタスクカードの合計

## バランス（1000シード、全員ボット / ランダム編成）

| 日数 | 中央値 | 星3 | 負債失敗率 |
|---:|---:|---:|---:|
| 10 | 31 | 113/1000 | 7.4% |
| 20 | 72 | 102/1000 | 6.5% |
| 30 | 116 | 109/1000 | 5.5% |

- 星の内訳（10日）: 0星 27% / 1星 47% / 2星 15% / 3星 11%
- 負債上限は負債分布のp95付近。失敗率は概ね5〜7%
- 戦略スプレッド（同一性格で全員プレイ）: 最強 finish+tidy+deadline と neutral の差は約13%

- WIP上限は撤廃。WIPは表示し、リードタイムとの関係を観察する
- タスク構成は通常42＋効果24＋インシデント6、リスクカード16枚の使い回し
- デッキ整理はレトロではなく、1アクション廃棄で行う
- 名前・性格ランダムのため、ゲームごとに得意/苦手が変わる
- 負債カードは全メンバーが片付ける。`greed` がマイナスのAIは追加でlv2/lv3カードを廃棄し、タスク報酬カードは残す
- `focus` がマイナスのメンバーは盤面の空きを見てPullを選ぶ
- 3軸の同じ評価式でプレイ/Pull/廃棄を比較する
- インシデントは優先的に処理する
